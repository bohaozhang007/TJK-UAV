# i7 编码规则

1. 精简、可读、功能完整，遵循“麻雀虽小，五脏俱全”；避免过度封装和不必要的中间层。
2. 函数定义和调用的参数超过两个时，换行写，每个参数单独一行；定义中的 `self` 也计入。
3. 所有 import 放在文件顶部，不放在函数内；必要的路径和环境配置放在相关导入之前。
4. 多个条件每行写一个，包括 `and`、`or` 和 NumPy 的组合条件，保留原有分组和优先级。
5. 代码注释、docstring、日志和报错全部用英文；本规则文件用中文。
6. 不写代码文件顶部的说明注释，只保留有助于理解逻辑的局部注释。
7. 库的默认参数已满足需求时，不重复指定。
8. 不用 `if __package__` 做兼容导入，直接导入同目录模块。
9. 不添加 requirements 文件。
10. URL、IP、端口、ROS 话题和服务名、阈值、超时等配置放在文件顶部，用大写常量命名，在代码中引用。
11. 独立功能按职责拆文件，`main.py` 负责流程调度；不为拆分而增加无用层次。
12. 简化前先判断是否有必要，以提高可读性为目的，不单纯减少行数。
13. 数据读取模块负责获取数据、提供时间信息和报告读取失败或超时；过期、配对等业务有效性由上层 `main.py` 判断。
14. Windows 端代码放在 `win/`，文件名不加 `win_` 前缀；通用工具代码放在 `util/`。

后续对话中用户明确新增或修改编码规则时，直接更新本文件；有冲突时以最新明确要求为准。不将一次性的业务需求自动扩展成通用规则。
